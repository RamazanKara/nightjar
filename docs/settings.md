# Settings reference

[Documentation](index.md)

Open **Settings** for **Video**, **Display & image**, **Controls**, **Audio**, **Streaming**, **App** and **Advanced**. Each row shows its current value. Explanations appear with the setting or through its info or **Help** button. **Advanced** includes decoder controls, input and network options, and diagnostics. Search matches setting titles, explanations and section names, including everything in Advanced. Selecting a result opens its section; Back returns to the same search, then to the section where you started. Global changes save automatically. Nightjar shows the options your device supports.

On a TV and on screens at least 840 dp wide, Settings shows two panes: the sections on the left and the chosen section on the right. Moving the D-pad or controller over a section shows it on the right straight away, with that section marked on the left; Center or Right moves into the section, and Left or Back returns to the section list before Back leaves Settings. A touch on a section shows it without moving focus. On a TV the list starts on **Controls** and focus on it, never on the toolbar. The list starts with **Search settings**, a focusable row (also on phones with a controller attached); search results fill the right pane and picking a section ends the search. Other screens can open a setting directly with `StreamSettings.open(context, section, focusKey)`: the section is shown, the setting selected and, with two panes, focused. Without a section, or with an unknown one, the key's own section is used; with neither the list opens and the log names the bad link.

**Profiles**, **Controller buttons**, **Keyboard shortcuts**, **GPU driver** and **Latency benchmark** share one focus rule: the first focus lands on their content rather than the toolbar when a remote, controller or keyboard drives them, and every button or row shows the same amber outline when it has focus ([SubPageFocus.java](../app/src/main/java/com/limelight/ui/SubPageFocus.java)).

The tables between the markers below are generated by [generate-settings.py](../scripts/generate-settings.py) from [preferences.xml](../app/src/main/res/xml/preferences.xml), the English resource strings/arrays, and the Java defaults and preset writes. Regenerate them after changing preferences; do not edit the generated rows by hand. [Documentation checks](building.md#documentation-checks) detect stale output.

Defaults describe a fresh installation before a preset or PC override. Changes to global stream configuration apply to the next stream. The stream menu exposes the controls that can change during a session.

| Match the screen to the game's frame rate<br>`checkbox_content_rate_frame_rate` | Off | On; Off | Enable on a screen with several refresh modes, with Allow lower refresh rate (or a Balanced with FPS limit or Smoothest video pacing) on. ## Per-PC stream profiles

Long-press a PC and choose **PC settings…**; the screen is titled with the PC name. Every value under **Stream** starts as **Same as all PCs**, which follows the main stream settings and the [named profile](#named-profiles-and-game-settings) in use, including later changes. A value that comes from a profile says so, for example *from profile Hotel*. Pick a value to give this PC its own; pick **Same as all PCs** again to follow the main settings. **Same as all PCs for everything** clears every value of this PC. Choose **Save** to keep the changes; leaving without saving discards them.

These controls are created in [HostStreamSettings.java](../app/src/main/java/com/limelight/preferences/HostStreamSettings.java), with validation in [HostStreamProfile.java](../app/src/main/java/com/limelight/preferences/HostStreamProfile.java).

| Setting | Values | When to change |
| --- | --- | --- |
| Video resolution | Same as all PCs, Native (follows this phone's screen), or width and height of 64–16384 pixels | Match a host display or choose a lower decode workload. **Use this screen** fills in the device's landscape dimensions. |
| Video frame rate | Same as all PCs, or 1–1000 Hz with up to two decimal places | Request fractional rates such as 59.94 or 119.88 Hz. **Use this screen** fills in maximum display refresh; VRR uses the panel maximum. |
| Video bitrate | Same as all PCs, or 0.5–2000 Mbps with up to three decimal places | Set this PC's bandwidth budget. The host applies its own ceiling; Nightjar follows the bitrate it reports. |
| Video codec | Same as all PCs, Automatic, Prefer AV1, Prefer HEVC, H.264, PyroWave | Compare codecs on this PC and device. |
| Upscaling / sharpening | Same as all PCs, or a mode with 0–100% sharpness | Choose a scaler for this PC's lower-resolution SDR stream. |
| HDR / Adaptive refresh (ARR / VRR) | Same as all PCs, On, Off | Enable for a compatible host and screen. |
| Frame pacing | Same as all PCs, Lowest latency, Balanced, Balanced with FPS limit, Smoothest video | Pick this PC's trade-off between latency and smoothness. Adaptive refresh replaces it with Lowest latency. |
| Host virtual display | Same as all PCs, On, Off | On asks the PC for a display matching this stream. Off leaves it to the PC's display settings. |
| Host render scale | Same as all PCs, or 50–200% | Change host render pixels relative to stream pixels. Used with the virtual-display request. |
| Prefer YUV 4:4:4 / Force full-range video | Same as all PCs, On, Off | Request supported chroma/range behavior for this PC. |
| Save | Action | Stores this PC's own values. Takes effect next stream. |

Profiles saved by builds up to test.10 copied every main setting. They now keep only the values that differ from the main settings, and VRR follows the main setting. Host device/app policy may override a request. The performance overlay and the log show the PC's own values and the display choice for each stream.

## Named profiles and game settings

A named profile is a set of stream values with a name, such as *Home 4K120*, *Hotel* or *Mobile data*. Open **Settings → Video → Profiles** to manage them. They are created in [StreamProfilesActivity.java](../app/src/main/java/com/limelight/preferences/StreamProfilesActivity.java), stored by [StreamProfiles.java](../app/src/main/java/com/limelight/preferences/StreamProfiles.java) and combined by [StreamLayers.java](../app/src/main/java/com/limelight/preferences/StreamLayers.java).

### Which value a stream uses

When a stream starts, each value comes from the first of these layers that sets it:

1. **This game**: the game's own values on this PC (game menu → **Stream settings for this game**).
2. **This PC**: the PC's own values (**PC settings…**, see [per-PC stream profiles](#per-pc-stream-profiles)).
3. **The profile**: the profile the network picked, or else the profile in use.
4. **The main settings**: everything under **Settings**.

On mobile data, **Bitrate on mobile data** then caps the bitrate, whatever layer set it. A layer that sets nothing leaves every value to the layers below. Profiles, PC and game values apply when a stream starts and never change during it; a reconnect keeps the network, and so the profile, that the stream started with.

Every value screen says where a value it doesn't set comes from: *from the main settings*, *from profile Hotel*, *set for this PC*. The Debug overlay and the Statistics status line show which layers a stream used, for example *Settings: profile Hotel, chosen for Mobile data + this game*. A profile picked by the network is also announced when the stream starts.

### Profiles

| Control | What it does |
| --- | --- |
| New profile | Asks for a name (1–32 characters, unique) and opens the new, empty profile. Set only the values it should change. |
| A profile → Edit values | The same rows as a PC's stream values: resolution, frame rate, bitrate, codec, upscaling and sharpness, HDR, adaptive refresh, frame pacing, YUV 4:4:4 and full-range video. Unset values say **Not set** and follow the main settings. A profile leaves host display choices to each PC. |
| A profile → Rename / Duplicate / Delete | Duplicate copies the values under a new name. Delete also clears the profile from **Profile in use** and every network choice; streams use the main settings instead. |
| Profile in use | The profile every stream uses when no network choice applies. **None** uses the main settings. |
| Choose by network | Off by default. On, the network a stream starts on picks the profile below; Ethernet and networks without a choice use the profile in use. |
| Mobile data | Mobile data, and Wi-Fi that Android marks as metered, such as a phone's hotspot. |
| Home Wi-Fi | The Wi-Fi networks listed under **Home Wi-Fi**. |
| Other Wi-Fi | Every other Wi-Fi, or every Wi-Fi while no home Wi-Fi is listed or the Wi-Fi name can't be read. |
| Home Wi-Fi → Add this Wi-Fi / Type a Wi-Fi name | Lists a home Wi-Fi by name. Select a listed name to remove it. |
| Next stream on this network | What a stream started now would use. |

Android shows the Wi-Fi name only to apps with location access. Nightjar asks for it only when you add the Wi-Fi you're on, after explaining why; typing a name needs no access at that point. Without access, home Wi-Fi can't be recognized when a stream starts: the Wi-Fi counts as other Wi-Fi and the stream says so. Mobile data and metered Wi-Fi are recognized without any permission. Wi-Fi names stay on this device and are never sent or logged; see [privacy](PRIVACY.md).

### Fallbacks

Nothing falls back silently. When the profile picked no longer exists or has a value this version can't read, the main settings apply and the stream says which profile was skipped. When a PC's or a game's stored values can't be read, that layer is skipped with a message and the layers below apply.

### Game settings

Open a game's menu and choose **Stream settings for this game**. The note under it says how many values the game sets. The screen has the same stream rows as a PC, plus the PC's virtual display rows where the host has them; values not set come from this PC, the profile and the main settings, in that order. Removing a PC removes its game values too.

A game's screen starts with a **Preset** row. Each preset sets only the values it names and leaves every other value of the game as it was, including the other two of frame pacing, adaptive refresh and bitrate. Nothing new is stored: the row names the one preset whose values the game holds, and says Custom when none matches, when two presets' values are both present (Smoothness with Quality, for example), and for a game with no values of its own. Resolution, refresh rate, codec and HDR are never touched.

| Preset | Sets | Leaves alone | Trade-off |
| --- | --- | --- | --- |
| Competitive | Frame pacing: lowest latency (the app default, set for this game so it holds if the main setting changes) | Adaptive refresh, bitrate | No extra delay. |
| Smoothness | Frame pacing: smoothest video; adaptive refresh off for this game, because it replaces frame pacing | Bitrate | Frames are held back, so latency goes up. |
| Quality | Bitrate: 150% of the PC's bitrate, or of the main settings' if the PC has none, at most the host's maximum (2000 Mbps) and, with automatic bitrate on for the PC and a maximum set, at most that maximum | Frame pacing, adaptive refresh | On a weak connection the larger frames can add delay. The bitrate is stored as a number, so a later change to the PC's or main bitrate shows the game as Custom. A named profile or the network never changes the base. |
| Custom | Nothing | Everything | Set each value yourself. |

Radeon settings per game (Anti-Lag, Chill and similar) are not part of the native API yet, so no preset changes them. That part waits for host support.

### Bitrate on mobile data

**Settings → Video → Bitrate on mobile data** (Off, 3–50 Mbps) caps the bitrate of a stream that starts on mobile data or metered Wi-Fi. It is separate from the profiles, so it protects a data plan whatever profile, PC or game value applies. The cap is decided at stream start; switching networks during a stream doesn't change it.

## Display on the PC

Open a PC's menu, choose **PC settings…**, then **PC display mode** under **Display on the PC**. Select a mode and confirm **Save display mode** to apply it from the next stream. **Cancel** leaves the saved mode unchanged. The display choice is saved separately from the stream profile. It is created in [HostDisplaySettings.java](../app/src/main/java/com/limelight/preferences/HostDisplaySettings.java) and stored by [HostDisplayChoice.java](../app/src/main/java/com/limelight/preferences/HostDisplayChoice.java).

| Choice | Sent to the PC | What the PC does |
| --- | --- | --- |
| The PC's own setting (initial) | Nothing, or `virtualDisplay=1` when **Host virtual display** is on | Follows **Host virtual display** and the PC's display settings. |
| Virtual display only (exclusive) | `hostDisplay=exclusive`, `virtualDisplay=1` | Adds a virtual display and switches the PC's monitors off during the stream. |
| Extend — keep PC display primary | `hostDisplay=extended`, `virtualDisplay=1` | Adds a virtual display beside the monitors; the PC keeps its primary display. |
| Extend — make virtual display primary | `hostDisplay=extended_primary`, `virtualDisplay=1` | Adds a virtual display beside the monitors and makes it primary, where games and new windows usually open. |
| Additional virtual display, separated from PC displays | `hostDisplay=extended_isolated`, `virtualDisplay=1` | Keeps the PC primary and places the virtual display away from the other displays. |
| Additional virtual display, main and separated | `hostDisplay=extended_primary_isolated`, `virtualDisplay=1` | Makes the virtual display primary and places the PC's other displays away from it. |
| Physical display (no virtual display) | `hostDisplay=physical` | Streams the PC's monitor, even when the PC or **Host virtual display** would add a virtual display. |

The PC puts its displays back when the stream ends. Separated displays still share the same Windows session; they are not separate user sessions. Only PCs whose host supports display modes (Rubylight 2.2.1 or later) offer the choice, and only those hosts are sent `hostDisplay`. Other PCs follow **Host virtual display**, which their stream settings show as a switch when the host has a virtual display. Remote Monitor and Remote Input keep the PC's settings.

## Reset scope

**Settings → App → Reset all settings** restores the global preferences and touch-mode flags. It keeps paired PCs, per-PC stream profiles and display choices, named profiles and their network choices, game stream settings, controller button mappings, the on-screen layout and the selected app language. Reset a PC profile in its own screen, a controller in **Controller buttons**, and the layout with **Reset controls layout**.
